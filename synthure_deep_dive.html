How to think like the person who built the system

When an interviewer asks about a tool, do not start with the tool name. Start with the input, output, error cost, baseline, trade-off, and evidence. This gives you six points of control in any technical discussion.

1 · Contract

What went in and what had to come out?

“An unstructured note went in. A validated encounter and four stakeholder reports came out.” Or: “ESPN plays went in; a grounded recap came out.”

2 · Decision

Where was uncertainty handled?

Identify every probabilistic decision, confidence threshold, fallback, verification rule, and escalation path.

3 · Evidence

How would I prove it works?

Know the baseline, the held-out examples, the exact denominator, the metric, the failure cases, and what was not measured.

4 · Operations

What would fail first in production?

Know latency, provider quotas, cache keys, concurrency, input drift, retries, downstream side effects, and safe degradation.

1. System contract and architecture

System contract: Take a clinical note, make a de-identified and normalized representation of what it actually says, attach allowed codes and published references, calculate explainable readiness and costs, then generate different views without allowing any view to invent medical or financial facts. Beginner

Imagine a medical receptionist who removes private information, a coder who checks diagnoses against a handbook, an insurance specialist who checks paperwork, four translators for four audiences, and an inspector who can reject the final reports.

Engineer

The browser loads three quantized OpenMed ONNX token-classification models via Transformers.js/ORT Web. It sends de-identified text and entity spans to POST /api/synthesize. The Node route loads gzip knowledge artifacts and JSON-exported classical ML models, performs deterministic evidence resolution, fans out Claude writer calls, audits/revises output, streams stage events over server-sent events (SSE), and seals a client-side SHA-256 audit record.

Ownership framing: “I separated evidence extraction, deterministic financial/clinical checks, probabilistic predictions, and language generation so that each failure could be detected at its own boundary.” The design matters more than whether it is called “multi-agent.”

Read in code

useSynthesis.ts (browser orchestration), route.ts (server pipeline), encounter.ts (shared portal state).

2. Walk an example through the entire pipeline

Illustrative synthetic example, not an actual run or clinical recommendation.

Input note (illustrative):
"Patient A, 58, with type 2 diabetes and right-knee osteoarthritis.
No chest pain. Elective knee surgery under consideration.
Medication details incomplete; payer prior authorization unknown."

Stage 1 — De-identify: replace patient identifiers, retain relevant clinical text.
Stage 2 — NER: detect {type 2 diabetes}, {right-knee osteoarthritis}, {chest pain}.
Stage 3 — Negation: 'no chest pain' is NOT evidence of active chest pain.
Stage 4 — Link: candidate ICD codes from official index; check billable/specificity.
Stage 5 — Readiness: check documentation, CPT, authorization status, code specificity.
Stage 6 — Write: patient explanation, clinical coder view, hospital claim view,
                  employer-level aggregate without patient identity.
Stage 7 — Gate: reject unsupported codes, numbers, prohibited medical advice,
                and inconsistent claims of 'ready to submit'.
Stage 8 — Output: show only accepted reports; otherwise revise/block/escalate.
Crucial distinction

Finding an entity is not the same as diagnosing it. Extracting “possible myocardial infarction” does not authorize treating it as confirmed. Linking a mention to an ICD code is not the same as declaring that code billable for that encounter. A note mentioning a prior authorization is not proof that the insurer approved it.

3. Extraction: de-identification, regex, NER, negation

Beginner

NER (named entity recognition) highlights meaningful spans of text such as a disease, medication, person, or dosage. Regex recognizes fixed patterns such as a code format. De-identification removes personal identifiers before external processing. Negation detection prevents “denies fever” from becoming “has fever.”

Engineer

OpenMed int8 ONNX token classifiers emit token-level labels and confidence. openmed.ts merges subword tokens back into spans and conservatively uses the minimum token score for the merged entity. route.ts adds a deterministic abbreviation map (HTN, T2DM, CKD, etc.) and a bounded negation-window heuristic. Server-side Claude span tagging can supplement extracted symptoms/labs, but it verifies that returned text exists verbatim in the source.

# Teaching pseudocode — not a copy of the production implementation
text = "Patient denies chest pain but reports SOB and HTN."
spans = ner_model(text)    # e.g., DISEASE spans with token confidences
spans += abbreviation_rules(text)  # SOB -> shortness of breath; HTN -> hypertension
for span in spans:
    if negated_in_local_clause(text, span.start):
        suppress_as_active_diagnosis(span)
    else:
        keep_with_provenance(span)

Why not only regex? It cannot easily recognize semantic variants, ambiguous abbreviations, or free-text descriptions. Why not only an LLM? It may invent fields, increases latency/cost, and needlessly exposes private text. Why not claim 100% privacy? Client-side de-identification lowers exposure but is imperfect: missed identifiers can still leak. A real deployment needs consent, security review, logging policy, access controls, and appropriate vendor agreements.

Debug tactic: inspect entity spans alongside their source offsets, type, confidence, negation context, and note section. Most downstream “reasoning errors” are actually misread inputs.

4. Classification: a small model can beat a giant prompt

Classification means choosing a label from a known set. In this system there are several distinct classification tasks, and mixing them up will create a bad interview answer.

Beginner

TF-IDF counts which words and word pairs matter in a document. Logistic regression learns how strongly those features predict each note type. A gradient-boosted tree asks a sequence of increasingly helpful yes/no questions about missing fields and note structure. You need not use an LLM for everything.

Engineer

classifyNoteType builds unigram/bigram TF-IDF vectors, applies exported coefficients per class, then a softmax to obtain a score. detectMissing evaluates per-field sigmoid classifiers over structured features. predictReadiness traverses a set of boosted trees, applies sigmoid and a stored isotonic calibration curve; current bands are ≥0.66 ready, ≥0.40 needs work, otherwise not ready. A predicted score is not proof that a claim will be paid.

Model training vs inference: training finds parameters from labeled examples; inference applies frozen parameters to a new note. In Synthure, the classical model artifacts are JSON, and TypeScript performs arithmetic at request time. The GPU-heavy training loop is not the same thing as the serving path.

Why calibration? A model returning 0.80 must not be interpreted as “80% of these cases are correct” until reliability diagrams / expected calibration error support that interpretation on independent examples. Isotonic regression learns a monotonic mapping from raw score to empirically observed frequency.

5. Retrieval: from a phrase to an actual ICD code

The current system's retrieval problem is controlled terminology linking: find official ICD-10-CM candidates for mentions such as “chronic obstructive pulmonary disease,” and ensure that a generated report cannot hallucinate a new code. This is different from searching a full insurer-policy PDF corpus.

Beginner

Think of the ICD index as a medical dictionary. Search the wording, get several plausible entries, then sort them by which one actually matches the diagnosis and how specific it is. Before accepting a code, check that it exists in the official list.

Engineer

icdCandidates() expands common clinical abbreviations, tokenizes a query, uses an inverted token index, first requires all terms and progressively backs off, then ranks by token overlap, matching head term, few extra words, and length. A separate exported logistic reranker uses features [overlap, termLen, billable, rank]. It scores with sigmoid(-2.9998 + 1.0865·overlap − 0.5506·termLen + 4.6580·billable − 1.2283·rank). The final code must validate against the ICD tabular. Feature weights being in code makes this a real deployed model, not simply a prompt claim.

Optional trained path: when SYNTHURE_MODEL_API points to a deployed model service, the route can call a trained bi-encoder retriever + cross-encoder reranker over roughly 98k FY2026 codes / 269k ontology phrase pairs. The service is optional; an unset or unavailable service does not prove that neural inference ran on a particular request. The repository reports a CodiEsp evaluation; because CodiEsp is translated Spanish-origin clinical text, it is not proof of US note accuracy.

What to measure: candidate recall@K (did you retrieve the correct code at all?), top-1 exact accuracy, MRR (how high was the first correct result?), billable-code errors, and abstention coverage. Separate candidate generation errors from reranker errors. Do not use MRR@5 0.91 from a profile headline as a current generalization result without its exact dataset and run.

A defensible retrieval answer

“I deliberately constrained the candidate space to the official ICD index. Candidate generation favors recall; ranking favors specificity and correctness; the tabular validator is the non-negotiable last check. An incorrect phrase link should be visible as a retrieval failure before the writer sees it.”

6. RAG, embeddings, IVFFlat vs HNSW: know the concepts, not a fictional deployment

Your older April 2026 PDF describes a different payer-policy RAG system: 512-token policy chunks with 64-token overlap, an e5-base-v2 dense retriever, top-K policy passages, and payer/effective-date filtering. It also reports a 200-pair retrieval benchmark. Those are claims in an older prep document; they are not established by the current code path. Learn them as a design and only say you shipped them if you can locate the actual pipeline/configuration.

Beginner

RAG gives the language model an open-book exam. Instead of hoping it remembers insurance policy rules, you look up the most relevant sections and put those passages into the prompt. Embeddings turn meaning into numbers so related phrases sit near one another. Vector search finds nearby numbers quickly.

Engineer

Index time: parse/version policy documents → section-aware chunks → dense vectors → metadata (payer_id, plan, start/end effective dates, source ID, version). Query time: normalize ICD/CPT + denial text → retrieve top-K within temporally valid documents → optional BM25+dense rank fusion → rerank → pass source IDs to the generator. Validate cited passage IDs and effective dates after generation. A semantic hit is not proof of coverage; policy conditions must still be evaluated against claim facts.

# Hypothetical policy RAG retrieval, for learning — NOT current Synthure code
candidates = vector_index.search(
    embed(f"ICD: M17.11 CPT: 27447 denial: medical necessity"),
    filter={"payer": payer, "effective_from <=": date, "effective_to >=": date},
    top_k=20,
)
ranked = rerank_against_full_query(candidates)[:5]
answer = model.generate(evidence=ranked, required_citations=True)
assert all(citation in ranked for citation in answer.citations)

The exact IVFFlat answer: “IVFFlat can reduce index memory and build overhead compared with HNSW, at the cost of recall unless I increase the number of probed clusters. I'd benchmark recall@5 and p95 against exact search on our corpus, not assume it wins.” But: no IVFFlat implementation or choice was verified in the current Synthure repository or the old PDF. Speak about this as a design trade-off unless you can show the index configuration.

K is a knob: too small loses evidence; too large adds model cost, latency, and irrelevant context. Pick K on a frozen retrieval test, not by intuition. Chunk size is a knob: smaller chunks localize rules but lose boundary context; overlap protects boundary-spanning conditions; section-aware chunks preserve policy structure. Time filters are mandatory: a January 2024 claim cannot use a rule adopted in July 2026.

7. Readiness, risk, confidence and routing

Beginner

A readiness score asks “does this paperwork look complete enough to proceed?” A denial predictor asks “will the insurer reject this claim?” They are entirely different labels. A threshold decides when software can proceed and when a human must inspect the result.

Engineer

assessReadiness() computes an explainable checklist and a review lane from validation failures and sourced prior-authorization rules. predictReadiness() computes a gradient-boosted score with isotonic calibration and fixed bands (0.66/0.40). inferReadmission() uses published CMS HRRP condition-level rates, not personalized patient prognosis. assessSafety() abstains if the minimum OpenMed extraction confidence is <0.60 or if no codes are resolved. Autonomous submission is not allowed by the three-tier action gate.

Do not say this

“Our model predicts 87% of claims will be denied,” “Our readmission rate predicts this patient's outcome,” or “Score 50 is a mathematically derived routing threshold.” The current shipped design explicitly removes denial probability. If an earlier prototype used a score of 50, explain it as a tuned operating point only if you have the historical code and evaluation.

How thresholds are actually selected: plot review rate, false-auto-approval rate, precision on automatically handled cases, and cost per case across candidate thresholds. Choose the operating point with acceptable safety cost. Record the metric, held-out split, and stakeholder-approved failure tolerance. A probability threshold is not meaningful until scores are calibrated.

Readiness is not payment: published CPT/fee schedule amounts and an illustrative deductible/coinsurance formula can estimate costs, but network contracts, benefits and adjudication rules may differ. Output numbers must be explicitly labeled estimates and trace to their inputs.

8. LLM inference and multi-agent architecture

Inference is using an already trained model to produce an output. For a generative language model, that means converting the prompt to tokens (prefill) and generating response tokens (decode). Every added source passage and every long answer consumes time and money. Orchestration means deciding the execution order, model, retry/failure boundary, and contract for each call.

01
Classical models & deterministic checks derive the encounter and readiness before prose is written. These are separate from the LLM.
02
Four parallel role writers receive the same verified fact sheet but different instructions. Patient: accessible language. Clinician: documentation & codes. Hospital: revenue workflow. Employer: de-identified aggregate.
03
Model routing sends most reports to Haiku; higher-readiness-risk clinician and hospital reports can route to Sonnet. The selection is driven by a deterministic review lane, not the model's self-reported certainty.
04
Combined verifier/constitution critic (Sonnet) audits all four reports in one call. The backend binds output to a typed tool schema, issues bounded revisions, then runs rule-based checks again.
05
Orchestrator composes a final cross-portal summary from the revised reports, while the route streams per-stage events to the client.
Beginner

One giant prompt might mix tasks together and produce a fluent but unverifiable paragraph. Specialized writers share the same trusted evidence, so a wrong code can be traced to retrieval, and a wrong sentence to a writer.

Engineer

Current route.ts uses Promise.all(STAKEHOLDER_ORDER.map(...)) for parallel role writers, Claude tool-use schemas for structured output, and a combined audit to reduce network fan-out. This is not four independent trained models: it is shared model families with different role contracts. A two-revision limit bounds recovery latency, though it creates a risk that later flagged reports remain unresolved and must be blocked/escalated by the final gate.

Why parallel rather than sequential? The four reports can be created from one immutable fact sheet; if each independently takes 0.8 seconds, sequential fan-out is approximately 3.2 seconds before auditing, while concurrent fan-out approaches the slowest call—unless API rate limits or shared contention dominate. Why a combined audit? Verification and constitutional critiques rely on the same fact sheet and reports, so merging reduces redundant model calls.

GPU nuance: this current implementation calls Anthropic's hosted models. You do not control its GPUs, KV cache, CUDA kernels, batch scheduler, or tensor parallelism. If asked about PagedAttention/vLLM, explain them as relevant to a separate self-hosted design, not as deployed Synthure code.

9. Why a correct deterministic layer can still produce a wrong report

A model can take correct ICD codes, pricing, and prior-authorization facts and still invent a medication, misstate the deductible, or advise treatment. The final generation layer needs its own verification boundary.

Guardrail examples verified in code: non-existent or ungrounded ICD/CPT codes; dollar/percentage figures that cannot be traced to known values; fabricated denial probabilities; prescribing/diagnosing language; PHI in the employer view; injected instructions echoed from a note; patient cost presented without “estimate”; “ready to submit” text inconsistent with the checklist. Checks cover input, grounding, policy, consistency, style, and quality.

Three-tier autonomy: draft/educate automatically; submit/message only after human approval; never independently diagnose, prescribe, or change treatment. That is a control on side effects, distinct from a text validator.

Beginner

The app should not publish a report simply because it sounds polished. It requires proof that its codes, costs, and statements came from the record. Certain medical actions are off limits even if the text looks plausible.

Engineer

The route calls assessSafety and runGuardrails, merges findings into targeted rewrite requests, reruns guardrails after revisions, and assembles a higher-level harness decision with human-in-the-loop escalation. An append-only hash chain in the demo makes local audit-record tampering detectable; it is not a substitute for server-side immutable storage or comprehensive HIPAA controls.

Direct interview line

“The deterministic layer constrains facts; it doesn't guarantee the LLM will repeat them faithfully. I run a second, independent output contract that can revise, block, or escalate before any report is trusted.”

There are three separate exams: did extraction capture the right facts, did retrieval return the right codes/evidence, and did the writer faithfully use them? A single end-to-end success rate hides the location of failures.

11. Serving, latency, observability, and the honest 10× bottleneck

Serving path today: local browser model weights load once and are cached; the app POSTs de-identified text to a Next.js Node route on Vercel; code/model artifacts are local to that function; Claude requests fan out; results stream through SSE. It has request/IP limits, a serverless duration cap, and an optional remote model-service dependency. The current demo maintains shared encounter state in the browser, not a server-authoritative multi-user database.

What p95 means: with 100 real requests, sort their durations and look near the 95th slowest percentile. End-to-end p95 is not the arithmetic sum of each stage's p95, especially with parallel branches. Instrument actual traces: de-id, NER, linking, writer fan-out, auditor, revisions, network and model time separately.

Safe retries: retry read-only classification or generation calls with bounded exponential backoff and jitter, but attach idempotency keys to side-effectful actions like submitting a claim or filing an authorization. The current demonstration's human approval actions are not proof of a production insurance filing system.

10× answer

“In this deployed shape I expect hosted LLM fan-out, third-party model-service cold starts, and per-request rate limits to dominate before local ICD lookup. I'd trace p95 by stage, cap concurrent writers, prioritize critical paths and cache stable evidence. For multi-user rollout, I'd first replace browser-only shared state with a server-authoritative encounter and idempotent events.”

12. The Synthure defense: one line first, then proof

Why multi-agent instead of one big prompt?

“I split evidence extraction, decision logic, audience-specific writing, and verification so each stage has an independently testable failure boundary.”

Engineering follow-up

Four parallel writers share one fact sheet; the combined auditor checks outputs; revisions are bounded and the final rule gate can block. A single prompt could be simpler, but loses observability and targeted recovery.

Why IVFFlat instead of HNSW?

“IVFFlat trades some recall for lower graph overhead and manageable builds; I'd tune lists/probes against exact-search recall and p95.”

The required caveat

This is a conceptual trade-off, not a verified choice in the public current Synthure code. Do not say “I deployed IVFFlat” without the index DDL or configuration.

What's your threshold actually doing?

“It's an operating point between missed errors and human-review volume, selected on validation data—not a theoretical constant.”

Which thresholds exist now?

Readiness uses 0.66/0.40 bands, safety abstains below 0.60 extraction confidence, and the role model selection uses readiness lane. The “50” from an older interview prompt has not been verified in this code.

What was your evaluation set and how did you avoid contamination?

“The public synthetic holdout is contaminated by its own generator, so I label it a regression floor; independent real-note generalization is still deferred.”

Owner-level depth

Describe grouped and temporal splitting, test freeze, prompt hygiene, hard-negative separation, and an independently annotated note corpus. Do not present the old 300-claim set as independent unless you can prove provenance and freezing.

What if the deterministic layer is right but the LLM is wrong?

“A post-generation validator checks grounding, costs, PHI and forbidden clinical actions; it can request a bounded rewrite, block, or escalate.”

Failure case

Valid ICD code entered, but the patient report invents a medication dose: the clinician fact sheet remains correct while the generated sentence fails grounding/policy and cannot be trusted.

Where does it break at 10× volume?

“First I would expect LLM API fan-out and optional model-service cold starts, then multi-user state consistency; I'd verify this with stage-level p95 traces.”

What not to say

Do not default to “we'd add eight GPUs” when the current runtime calls a hosted Anthropic API. A self-hosted inference design has a different bottleneck.

What exactly does the retrieval model learn?

“The logistic reranker learns candidate ordering from lexical features; the optional bi-encoder learns phrase-to-code similarity and its cross-encoder learns pairwise discrimination.”

Why not predict denial probability?

“We don't have trustworthy paid-versus-denied adjudication labels, so we expose sourced readiness checks instead of presenting an invented probability.”

What is the limitation of your red-team pass rate?

“It proves our rules catch the handcrafted attacks we tested, not that the system is robust to unseen clinical or prompt-injection failures.”

What part did you actually own?

“I can explain the contracts between browser extraction, ICD resolution, readiness, role writers, audit, and the client state because the design exposes each decision and its source.”

Personalize to your actual contribution

Replace “I built” with the precise modules and actions you personally implemented. The repository can verify mechanics, but it cannot independently establish individual contribution or production scale.

STAGE 01 / 14

Clinical input, de-identification and trust boundaries

Beginner / what happens

A patient note may include a person's name, symptoms, medications, insurance information and clinician language. The first goal is not to generate an answer. It is to decide which parts of the text can safely pass downstream. Browser-side OpenMed de-identification identifies and masks personal information before the Next.js synthesis endpoint receives the note. A separate clinical NER model reads medical spans.

What did the system return?

A de-identification model outputs entity spans such as PERSON, DATE or ID with boundaries and confidence values. The code aggregates token predictions to spans and conservatively uses the lowest token confidence within a merged span. Think of the result as an annotated note plus an audit of redaction counts, not a chatbot response.

What did we actually find?

In the committed evals.json, seeded-span de-identification recall is 1.00 on a low-trust synthetic benchmark. This is a useful regression check, not a verified zero-leakage guarantee for all real PHI or a HIPAA certification. Because false negatives can reveal information, external real-note review remains necessary.

Engineer / how to defend it

Mechanically, the browser loads local quantized ONNX OpenMed weights via transformers.js and ONNX Runtime Web. It sends de-identified text and derived entities to /api/synthesize. STAGE 02 / 14

Document classification: where TF-IDF and logistic regression help

Beginner / what happens

Before reading a note, the application asks what kind of note it is: SOAP, referral, discharge summary, ER note, radiology report and so on. A classifier selects one category. That matters because the expected fields and downstream suggestions differ by note type. Classification is the task of choosing a label; it is not the same as recognizing entities inside the text.

What did the system return?

The note-type classifier converts words and two-word phrases into TF-IDF features, applies learned linear weights for each class, then softmax to report the most likely class and a score. For a referral with phrases such as 'refer to cardiology', a possible output shape is type='referral', confidence=0.87—an illustration, not a captured production prediction.

What did we actually find?

The repo's synthetic note-type accuracy is 1.00 on 360 examples, explicitly flagged as contaminated by template-label leakage. The real held-out accuracy is deferred. Inspect classifyNoteType in frontend/lib/models/synthure.ts: the tokenizer constructs unigrams/bigrams; TF-IDF scores are normalized; linear class scores pass through softmax. STAGE 03 / 14

NER: model spans versus rigid patterns

Beginner / what happens

Named entity recognition, or NER, marks substrings that name meaningful things: diseases, medications, dates, doses and other entities. Instead of answering the whole medical question, the model produces where each entity begins and ends. Regex is better for a code format with known syntax; NER is useful for a phrase written in many possible ways.

What did the system return?

An OpenMed token classifier can produce tags like B-DISEASE and I-DISEASE along with per-token scores. The code stitches adjacent tokens into a full mention; for example, 'chronic kidney disease' becomes one span with a conservative confidence. A model may miss abbreviations, so a deterministic shorthand pass supplements it.

What did we actually find?

The committed seeded-span suite reports disease NER recall 0.830 and pharmaceutical NER recall 0.944. These are limited to synthetic notes with seeded spans and incomplete annotation; the benchmark cautions that some apparent false positives may be legitimate unannotated entities. Recall is the share of true mentions recovered.

Engineer / how to defend it

Key engineering choice: separate structured and unstructured extraction, and preserve source labels so you know whether a candidate came from OpenMed, literal text or a model-linked code. Never turn an entity string into a billing code without validating it. Missing the mention changes the ceiling of every later stage.

Test, failure mode, and improvement

Probe 'no asthma', 'denies cough', misspellings, brand vs generic medications and multiword diseases. Track entity-level precision, recall, F1 and the exact span error; a single missed qualifier can alter clinical meaning.

STAGE 04 / 14

Clinical shorthand and negation: why a model cannot be trusted alone

Beginner / what happens

Clinical notes compress terms: HTN means hypertension; DM2 refers to type 2 diabetes; SOB is shortness of breath. A literal NER model may miss them. The code therefore maps known abbreviations to canonical phrases. Equally important, if a physician writes 'no fever', recognizing FEVER is not enough: the system must also understand that the condition is negated.

What did the system return?

For an illustrative note 'HTN, no fever', the deterministic extraction should add a hypertension mention and avoid treating the fever as present. This is a rule-driven response, not a neural model predicting a disease. The negation check inspects a short window before a candidate span and stops at a clause boundary.

What did we actually find?

The repo documents this safety mechanism, but it does not publish a dedicated real-world accuracy number for negation scope. What we can observe is the implemented decision rule and its failure surface. A rule can mishandle 'not only hypertension but also diabetes', long-distance negation, or complex syntax.

Engineer / how to defend it

Review CLINICAL_ABBREV and isNegated in the synthesis route. The latter uses a 22-character window and regex cues, making its assumption explicit: nearby negation words often apply to the following term. Domain semantics beyond that window require stronger parsing or clinician review.

Ranking candidate codes with a learned scorer

Beginner / what happens

Retrieval can return eight plausible entries. The next problem is ranking: which should be first? A reranker assigns a score to each candidate so the best-supported codes rise to the top. Logistic regression is useful here because candidate features are small, explicit and debuggable.

What did the system return?

The current reranker looks at lexical overlap, length of matched term, whether a code is billable and its initial retrieval position. It computes a weighted sum and turns that into a 0–1 score with the sigmoid function. The returned number is a ranking score; it is not necessarily a probability that a clinician would approve the code.

What did we actually find?

The synthetic top-1/top-3 coding figures above measure the constrained coding pipeline. Separately, a trained bi-encoder / cross-encoder coding experiment on translated CodiEsp examples reports acc@1 0.4066, acc@5 0.4918 and MRR 0.4443 on 3,615 cases. Those domains are not directly comparable.

Features are exported in frontend/lib/models/reranker.json and calculated in models/synthure.ts. Section parsing and missing-documentation detection

Beginner / what happens

A medical note has parts like 'history', 'assessment' and 'plan'. What did the system return?

The parser produces named spans. The missing detector produces a per-field score that represents its learned belief a field is present or missing, using simple structural features. What did we actually find?

Engineer / how to defend it

Section parsing is explicitly rule-based; missing-field models are per-field logistic regression. Both should preserve the evidence string that caused a flag. Distinguish a field truly absent from one that is present in an unfamiliar format or elsewhere in the note.

STAGE 08 / 14

Readiness prediction, calibration and human-review routing

Beginner / what happens

Readiness is not the same as denial probability. The model estimates whether claim documentation is ready or needs work, using information such as note type, number of diagnoses, procedure entries and completeness indicators. A gradient-boosted tree model combines many small decision trees; isotonic calibration adjusts its raw output so its numerical confidence better matches observed frequencies.

What did the system return?

After applying the calibration curve, the runtime groups scores into ready, needs_work and not_ready, using code thresholds 0.66 and 0.40. It also runs deterministic checks for prior authorization and documentation issues. The final reviewer lane can be influenced by blocking flags, separate from the model's score. A score does not authorize a claim submission.

What did we actually find?

On the synthetic test set (n=360), readiness AUROC is 0.839, AUPRC 0.904, calibrated ECE 0.054, overall accuracy 0.883 and accuracy among confident cases 0.917. These measure a controlled label distribution; no real adjudication-based denial predictor is supported by the current repository.

The implementation evaluates gradient-boosted decision trees and maps the raw probability through an isotonic lookup. The safety layer abstains if extraction confidence is below 0.60 or no codes are resolved. This is distinct from the older score >= 50 CV routing narrative, which is not the current public route condition.

Study handbook · core ML and backend concepts

Learn the fundamentals until you can explain them without a prompt

Use the Beginner/Engineer switch at the top. Definitions below are deliberately operational: they say when to use the concept, which project uses it, and how it fails.

Binary classification

One of two labels, e.g. “field present / absent.” A sigmoid gives a score; a threshold maps it to a decision. Synthure: missing-documentation fields.

Multiclass classification

Exactly one label out of several, e.g. note type = SOAP, ER, discharge, etc. Typical output uses softmax. Synthure: note-type model.

Multilabel classification

Many labels can be simultaneously true, e.g. a note can mention diabetes, hypertension and arthritis. Use separate per-label scores, not one softmax. Would apply to document diagnosis tagging.

NER

Named entity recognition: locate spans and assign types (DISEASE, DRUG, PERSON). BIO labels represent Begin/Inside/Outside. Errors include span boundaries and false positives under negation. Synthure: OpenMed token classifiers.

Regex / rule engine

Pattern matching, no learning required. Great for explicit formats, source IDs and known play phrases; weak on semantic ambiguity. Synthure abbreviations; Replays play types.

TF-IDF

Word frequency weighted down for common words across documents. Sparse features feed simple classifiers or keyword retrieval. Synthure note-type classification.

Logistic regression

Weighted feature sum passed through sigmoid for a score. Fast, simple, interpretable; doesn't directly understand long contextual dependencies. Synthure missing fields + reranker; Replays curation.

Gradient-boosted trees

Many small decision trees sequentially correct predecessor errors. Strong for tabular and structured features. Can overfit synthetic labeling rules. Synthure readiness.

Embeddings

Dense numeric vectors representing tokens, phrases or documents. Similar meanings may be near in vector space. They are not proof of factual equivalence. Optional Synthure trained coder; older policy-RAG design.

RAG

Retrieve sources at query time and condition a model on them. Helps with changing knowledge and citations; adds retrieval errors. Older Synthure policy narrative; distinguish from ICD linking.

Bi-encoder vs cross-encoder

Bi-encoder embeds query and item separately so search is fast; cross-encoder reads both together to score relevance more accurately but is costly on many candidates. Synthure optional trained ICD coder.

IVFFlat / HNSW

Approximate nearest-neighbor vector indexes. IVF searches selected clusters; HNSW navigates a neighborhood graph. Trade recall, speed, RAM and build costs. Know theory; not verified deployed in current Synthure.

Model inference

Run a trained model on an input. For a text LLM: tokenize, prefill context, decode output. Latency depends on context length, generated tokens and queueing. Synthure writers; Replays recap.

GPU + KV cache

GPU parallelism accelerates matrix ops; KV cache stores attention keys/values for earlier tokens. Long prompts and many concurrent streams consume VRAM. Relevant to self-hosted inference, not directly controlled by current hosted APIs.

LoRA / QLoRA

Efficient fine-tuning with small trainable adapters; QLoRA quantizes the frozen base. Saves training VRAM but still needs datasets and evals. Replays offline training scripts.

Distillation

Teacher-generated supervision trains a smaller student. Caveat: teacher mistakes and leakage become student training data. Replays newsletter and broadcast training design.

Calibration

Does a predicted 0.8 correspond to ~80% positives across similar predictions? Check reliability and ECE; recalibrate using held-out validation. Synthure readiness isotonic mapping.

Precision vs recall

Precision = share of predictions that are right. Recall = share of actual positives recovered. In high-stakes extraction, false negatives vs false positives have different downstream costs. Both systems: NER/play detection.

MRR / Recall@K / NDCG

Retrieval ranking metrics: first correct rank, any correct in top K, and graded rank quality. Don't claim model performance without exact gold set. Synthure ICD linking; Replays curation.

Data contamination

Test labels or near-duplicate examples leak into training, prompts, retrieval artifacts or tuning loops. Prevent with grouped temporal splits and frozen holdout. Synthure synthetic generator; Replays same-game splits.

SSE / WebSocket

SSE is server→client event streaming over HTTP; WebSocket supports bidirectional communication. Streaming stages is not the same as durable cross-device synchronization. Synthure SSE route.

Redis TTL + sorted set

TTL expires cache keys; sorted set supports ranked leaderboards. Watch cache staleness and concurrent increments. Replays caches, points and rankings.

Idempotency

The same request retried twice must not cause duplicate side effects. Use stable IDs and atomic state transitions, not only a read-then-write check. Replays pick resolution; future Synthure claims.

p95 and tail latency

95th-percentile request duration, more revealing than an average for slow users. Parallel stages make naive sums misleading. Both applications' serving design.

Abstention / human-in-the-loop

The system withholds automation when evidence or confidence is insufficient. Track both the error rate on automated cases and coverage. Synthure 0.60 extraction confidence gate.

Why is NER a different problem from note-type classification?

NER predicts typed spans and their positions, possibly many per document. Note-type classification predicts a single document-level label. They need different labels and error metrics.

If recall@5 is 90% but generation accuracy is 70%, where do you look?

Inspect whether the relevant evidence actually survived reranking and prompt assembly; then check citations and model interpretation. Also verify the remaining 10% retrieval misses aren't concentrated in high-risk cases.

Why can a 0.9 model score be unsafe?

Raw scores are not necessarily calibrated and may be out of distribution. A high score can coexist with missing information; validation and safety checks still apply.

What is the difference between a cache and a database?

A cache stores temporary reusable results with invalidation/freshness semantics. A database preserves source-of-truth state and transactional consistency. Redis can serve as either for certain data, depending on durability and write guarantees.

Why is “four agents” not necessarily “four models”?

Different prompts, deterministic roles or functions may execute on the same base model or no trained model at all. An agent is an orchestration boundary, not proof of independently trained weights.

Why might an ANN index return wrong candidates even when the vector is good?

Approximate search skips parts of the space. Index hyperparameters, filters, stale vectors, and reranking can all affect recall; compare with exact nearest-neighbor search.

How can a Redis pick be awarded twice despite checking “resolved”?

Two requests both read the unresolved state before either writes. Make compare-and-update and points award one atomic Redis operation.

What is one thing you should never invent in an AI systems interview?

A latency, benchmark denominator, fine-tuning run, model deployment, dataset provenance, user count, partner contract, or production architecture that you cannot verify. Explain your design decisions and known limitations instead.
